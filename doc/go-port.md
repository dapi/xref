# Go-порт для Ruby/Rails

Это ранняя Go-реализация ядра xref. Исходный Ruby-движок и [спецификация](guide.md)
сохранены в форке как эталон. Автор исходной идеи и спецификации — Nik Grebnev;
условия использования находятся в [LICENSE](../LICENSE) и
[LICENSE-docs](../LICENSE-docs).

Go-порт строит локальный индекс Ruby-кода и дампа `db/structure.sql`. Он
использует Tree-sitter для Ruby и парсер PostgreSQL для SQL. Индекс лежит в
пользовательском каталоге кэша за пределами анализируемого проекта. Код и
содержимое БД никуда не отправляются. Для сборки нужен Go и C toolchain,
поскольку оба парсера используют cgo.

## Сборка и запуск

Из корня этого форка:

```sh
go build -o bin/xref-go ./cmd/xref-go
```

Из корня анализируемого Ruby-проекта:

```sh
~/code/xref/bin/xref-go refresh
~/code/xref/bin/xref-go where products.id
~/code/xref/bin/xref-go find 'Product.where'
~/code/xref/bin/xref-go blind
~/code/xref/bin/xref-go audit
```

Если дамп схемы находится в другом месте, передайте `--schema repo=путь` до
команды. Несколько источников позволяют сравнить схемы:

```sh
~/code/xref/bin/xref-go --schema stage=/path/to/stage.sql \
  --schema prod=/path/to/prod.sql drift
```

`--project` задаёт корень проекта, `--json` выводит машинный результат,
`--limit` ограничивает печать строк. `blind` исключает тестовые файлы по
умолчанию; `--include-tests` включает их. Короткий текст `find` ищется буквально
без учёта регистра. Поле `file_tables` в JSON означает таблицы, найденные где-то
в файле, а не на строке совпадения.

## Что уже работает

- `where`: обращения к таблице или колонке в разобранном SQL и распознанных
  вызовах ActiveRecord; уровень достоверности показан у каждой записи.
- `find`: поиск по текстовым файлам проекта с отметкой, проиндексирован ли файл.
- `blind`: возможные обращения к таблицам, отсутствующим в выбранном дампе.
- `drift`: различия таблиц и колонок между двумя или более дампами.
- `audit`: объём индекса и его наблюдаемые пробелы.
- Пересканирование изменённых файлов перед каждой командой. Изменение бинарника
  или схемы вызывает полное пересканирование.

## Границы этой версии

Это **не функциональный эквивалент** исходного xref. Ruby-метапрограммирование,
модели в переменных, сложные правила инфлексии, SQL-фрагменты, шаблоны ERB/Haml/Slim,
живые схемы окружений, production-логи и остальные команды исходника пока не
поддерживаются. `audit` сообщает количество разобранных файлов, ошибок Ruby,
неразобранного SQL и пропущенных шаблонов. `blind` по модели, имя таблицы которой
выведено по соглашению Rails, является кандидатом для ручной проверки.

Перед использованием результата для изменения БД проверьте конкретную находку
по исходному файлу и фактической схеме нужного окружения.
